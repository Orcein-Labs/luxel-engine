# Engine readiness reset

October 12, 2026. User direction after reviewing the dry ruin scene and the
rejected Heartwood experiment: develop the reusable engine capabilities needed
for quality and variety. This changes the next-work priority from polishing
the forest profile to diagnosing and closing foundational gaps.

## Evidence and limits

This inventory describes the current native path in the isolated continuation
worktree. It does not audit every other backend or incorporate the primary
checkout's uncommitted character/avatar work. Existing capabilities and
experiments remain useful; none establish a complete creative engine.

The actual baseline/cascade/contact/Heartwood/combined CLI matrix completed
all fifteen captures. That establishes execution through the supervisor, not
visual acceptance. Heartwood's medium image fails: mostly bare poles, weak
canopy, untextured trunks and a flat path strip. The dry ruin calibration
layout is not an authored Riverwatch environment despite its input filename.

## Development order

1. Establish a reusable native material and foliage inspection scene: known
   opaque/cutout/blended cases, atlas preview and UV coverage, surface scale,
   roughness/normal response and two-sided behavior. Include moving cameras
   and depth diagnostics. Unsupported execution must be explicit. Diagnose
   Heartwood here before changing the large scene again.
2. Close the material/lighting foundations exposed by that scene. Start with
   the failures it actually demonstrates; avoid a speculative universal
   rendering framework. Calibrate exposure and environment contribution,
   then add bounded local lighting and required material families through
   typed execution paths.
3. Prove generality with small, deliberately different scenes: a temperate
   forest, a dry built environment and a stylized scene. Use shared engine
   facilities with authored inputs. Each must demonstrate distinct geometry,
   surfaces and lighting; tinting a single scene does not establish variety.
4. Establish motion and runtime quality before declaring scene parity:
   moving-view aliasing/shadows, wind/animation, resource reuse and measured
   warm budgets. Add a character/puppet acceptance scene separately from
   environment graphics.
5. Return to the forest settlement as an integrated acceptance environment.
   Cinema, interactive worlds, avatars and wallpapers then receive explicit
   product acceptance tracks over the shared core.

This ordering supersedes immediate forest beauty iteration in the recovered
continuation order. The existing correctness/resolution/cascade/contact
receipts remain valid within their measured scope. No default promotion of
the rejected forest or IBL experiment is authorized by a technical pass.

## Acceptance discipline

Every capability needs three independent answers: does it execute correctly,
does the actual image or motion meet its visual purpose, and does it fit its
runtime budget? Tests, human visual review and performance receipts answer
different questions. Pixel diversity, instance counts and output alpha are
diagnostic proxies; they are not measures of beauty or commercial parity.

Retain failed renders and distinguish content, authoring, renderer and evidence
failures. Change the smallest responsible layer. A reusable engine improvement
must work outside the one scene that motivated it. Do not announce a whole
style or application as supported from a schema, a lowering plan or a still.
